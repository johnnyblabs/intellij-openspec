# OpenSpec CLI 1.17 — Feature Delta & Plugin Impact (vs 1.16.1)

> Every upstream claim below is cited to the [OpenSpec 1.17.0 changelog](https://github.com/Fission-AI/OpenSpec/blob/v1.17.0/CHANGELOG.md) and checked against the captured CLI output under `../../src/test/resources/fixtures/cli/1.17.0/`.

## 1. Summary

1.16.1 → 1.17.0 changes only `openspec update` and how it cleans up old generated files. No command, flag, workflow, workflow template, AI-tool entry, validation rule or JSON shape the plugin reads changed. Every 1.17.0 capture equals its 1.16.1 twin apart from the version number, so 1.17 support is capture-and-declare.

## 2. Delta table

| # | Upstream change (1.17.0 changelog) | Kind | Plugin |
|---|---|---|---|
| 1 | Command files are deprecated and go away in OpenSpec 2.0; `openspec update` says so and names the switch to skills-only delivery — #2213 | Deprecated | ✅ nothing the plugin parses changed; command delivery keeps working on 1.x |
| 2 | Switching to skills-only delivery removes only the command files OpenSpec generated; edited ones are kept and listed — #2213 | Fixed | n-a (the CLI's own file handling) |
| 3 | `openspec update` upgrades a project from any release since 0.12 in one run, removing unedited old OpenSpec files without `--force` and keeping edited ones — #2213 | Modified | 🟡 the existing update-preview cases plan exactly as on 1.16.1; how the preview presents the new unasked removal is follow-up work |

## 3. Verification

- Parity corpus: default and `--strict` verdicts equal 1.16.1's (only timings differ), so the anchors stay default `1.8.0` and strict `1.6.0`, with the archive-drop divergence pinned from `1.14.2`.
- AI-tool registry (50 tools), detection cases, `init --help`, workflow ids, design and specs instructions, explore and update listings, workflow invocations, explore context and the update dry-run cases: identical to 1.16.1 apart from the version.
